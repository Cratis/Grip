# Learn this project's conventions

This project was not scaffolded by the kit. Before any slice is built here, record how this project is written so every later build follows it.

Read the solution and project files, two or three existing features end to end, their specifications and their frontend. Do not change any file except the one below.

Write `{conventions}` as short Markdown with these sections, each a list of facts you saw, with one example path per fact:

- **Projects**: the solution file, the web project, the specification project, and their root namespaces.
- **Slices**: where a slice lives, how its files are split, and how namespaces follow folders.
- **Commands and events**: how commands, validation, events and concepts are written.
- **Read models and queries**: projections or reducers, query style, observable or snapshot.
- **Automations**: how reactors are written and registered.
- **Specifications**: the framework, base classes, folder and naming pattern, and the command that runs one feature's specifications.
- **Frontend**: the page, dialog and routing pattern, and where proxies are generated.
- **Verification**: the exact build and test commands that must pass.

Where the project differs from the kit's stack instructions, the project wins; say so under **Differences**. Do not guess: write "not seen" for anything you did not find.
